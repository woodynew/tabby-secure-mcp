# 按客户端管理连接授权：实现与验证

日期：2026-11-15。开发分支：`codex/secure-mcp-remediation`。本轮在已有内嵌 HTTP 候选上增量修改，交付到该开发分支；未推送、发布或更新个人 Tabby 安装。

## 已实现

- 复用现有命名凭据的配对预授权，设置中明确标注 `MCP access authorization (pairing)`，保留下次会话、24 小时、永久、清除。
- 每个客户端卡片提供 `SSH connection authorization`，对每个白名单 SSH 配置选择 `Ask when used` 或 `Permanently allow`，客户端不必已在线。
- 连接许可按凭据和配置摘要保存，不按名称匹配。打开与命令工具均检查；旧全局打开许可不再赋予客户端连接权限。SSH 白名单及命令等级继续独立生效。
- 未预授权时保留弹窗，展示真实客户端名称、目标和实际操作；允许后只记住该客户端与目标，单条命令只创建一个请求专属标签页。
- 凭据格式 v2 兼容读取 v1，成功保存时升级且不旋转 token。重命名及配对时效修改保留连接许可，凭据重置清空许可，撤销删除许可。
- 新增连接许可修订号与待保存拒绝状态。旧弹窗、旧写入及 SSH 就绪前的请求不能覆盖更新的撤销；持久化失败提示用户，当前运行保持拒绝。
- 设置页在凭据变化后重新计算连接状态，在 Tabby 配置变化时重载配置快照，并防止较早的异步重载覆盖较新快照。
- `get_ssh_operation_authorization.open_session` 表示当前认证客户端对目标的有效连接许可。四个工具输入保持兼容。

## 兼容与操作边界

旧共享打开许可不会自动扩散到所有客户端，升级后应在客户端卡片中预授权，或通过首次使用弹窗。旧插件不能读取 v2 凭据文件，降级需先备份私有状态并安排兼容恢复。

撤销不能撤回已经发送的远端命令；未知结果仍不得自动重试。未成功持久化的撤销不保证跨重启，必须按设置提示重试保存。未运行 Windows/Linux GUI、Node 20 或远端 CI 验证。
