# SSH 文件传输与连续开发问题修复

日期：2026-11-17。

## 已修复问题

- 修改客户端配对有效期时，保留该客户端各 SSH 的命令集、全局继承选择和文件传输选择；重置或撤销凭据仍按原规则清除授权。持久化失败时继续拒绝访问，避免其他保存路径意外恢复旧授权。
- 用户在 MCP 创建的终端输入后，该标签退出自动复用和自动关闭。监听从标签创建时开始，覆盖前端尚未就绪以及首次命令发送前的窗口；MCP 自己发送命令不会被误认为用户输入。显式关闭工具仍可用，AI 工具说明要求尊重用户接管。
- 上传独占创建的响应丢失时，返回 `outcome_unknown`，不误报为确定未写入，也不以弱化的标志重试创建或删除可能存在的远端文件。

## 文件传输

新增 `upload_ssh_file` 和 `download_ssh_file`，MCP 工具总数为 7。

在设置页各客户端下的 SSH 行增加“启用文件传输”，默认关闭，按凭据身份与 SSH 配置摘要单独保存。全局命令集继承、命令审批模式及“完全访问”不启用此权限；仅设置页可开启，MCP 无法自行授予。升级旧凭据时全部保持关闭。

参数均为 `profile_ref`、`local_path`、`remote_path`。本地路径指 Tabby 所在机器，使用 Tabby 进程的操作系统文件权限。仅支持单个普通文件、绝对路径、最大 64 MiB、服务端 180 秒期限；目标文件不得存在，父目录须已存在。暂不支持覆盖、目录递归和断点续传。

传输使用 Tabby 原生 SFTP，优先复用同客户端同目标的空闲 MCP SSH 连接，否则经过现有连接授权新开可见标签。返回状态、字节数及保留标签的 `tab_ref`/`tab_reusable`。权限撤销、客户端身份或目标配置变化会停止传输，已写入的字节无法撤回。

上传失败可能留下远端部分文件。`outcome_unknown` 要求检查文件和标签后再决定后续操作，禁止自动重试；插件不删除无法证明归属的远端目标。下载失败只在仍可确认本地目标身份时清理自己的部分文件。

私有凭据格式升级为 v4，可读取 v1/v2/v3；旧版插件无法读取 v4，降级前须保留私有备份。升级不主动轮换现有 token。
