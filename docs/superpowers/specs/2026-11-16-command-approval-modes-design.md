# SSH 命令审批模式设计

日期：2026-11-16。状态：用户已确认，已实现，正在完成验证。

## 目标与已确认需求

将 SSH 配置中的命令权限等级替换为三种审批模式：请求审批、自动编辑、完全访问。解决已允许读写却因未知程序分类而直接拒绝普通查询的问题。

用户已明确选择：审批记忆按“当前客户端＋当前 SSH 配置＋程序和子命令”永久保存；审批框显示实际范围并能清除。复杂或无法可靠划分的命令回退为完整命令匹配。

2026-11-16 补充需求：每个客户端的每个 SSH 配置分别维护审批命令集，支持编辑、清空、复制并粘贴到其他 SSH 配置。增加全局默认审批命令集；用户已明确选择“默认继承、全局修改同步生效”，每份命令集可以关闭继承。

保留命名客户端、SSH 白名单、按客户端的连接授权和四个 MCP 工具。三种模式控制命令审批，不替代客户端认证或 SSH 连接授权。

## 实现方式

推荐在现有单命令解析器、审批调度器和凭据存储上增量实现。参考 OpenCode 的逐项授权和审批记忆，但不直接复用它的自动前缀：`uci *`、`nft *` 和 `ip -4 *` 都过宽。

另一种做法是移植完整 OpenCode Shell 扫描器与规则引擎。它有利于支持复杂 Shell 语法，但本项目当前明确限制单命令，不需要为本次需求增加这部分功能和依赖。本设计采用前一种方式，供用户确认。

## 审批模式

| 模式 | 未记住的低风险命令 | 高危或未知命令 | 审批记忆 |
| --- | --- | --- | --- |
| 请求审批 `ask` | 未被有效审批命令集覆盖时请求审批 | 未被有效审批命令集覆盖时请求审批 | 命令集由用户在审批框或设置页明确授权，匹配范围必须展示 |
| 自动编辑 `auto_edit` | 自动执行 | 每次请求审批 | 高危/未知命令不使用历史记忆，不提供永久免审 |
| 完全访问 `full` | 自动执行 | 自动执行 | 不需要命令审批记忆 |

“请求审批”包含读取命令的首次使用；选择“允许一次”不建立记忆。“完全访问”提供远端 SSH 账户所拥有的命令能力。

继续保留“禁止执行命令”的能力，独立于三种模式表达，兼容旧 `none` 状态。禁用时不弹命令审批，也不发送命令。

模式在每个 SSH 配置行管理，适用于已通过其他授权检查的客户端。模式变更立即作废相关待审批/待发送请求；补充需求后，命令集作为用户可管理的数据保留，不因切换模式自动删除。切回请求审批时按设置中展示的有效命令集授权；切到自动编辑时高危/未知仍逐次审批，切到完全访问时命令集不参与放行判断。

## 命令解析与风险

保留单命令、512 UTF-8 字节、控制字符拦截、参数引用编码等执行边界。管道、重定向、分号、命令替换和换行不因完全访问而开放。本次不加入 LLM 判定器，也不执行命令来探测风险。

风险判断与模式授权拆开：已识别且参数受限的查询、普通目录创建和文件触碰可作为低风险；删除、覆盖风险、权限变更、服务/网络配置变更、系统目录修改、解释器和未知参数均需审批。自动编辑采用正向规则，不能把“未命中高危正则”当成低风险。

初版至少覆盖以下正向查询，并为同程序的修改动作提供反例：

| 查询 | 低风险识别范围 | 自动编辑下需要审批的相关操作 |
| --- | --- | --- |
| `docker ps` | 明确支持的 Docker 查询子命令及参数 | `docker run/exec/rm`、清理操作、未知选项 |
| `ip -4 rule show` | 保留地址族选项并明确识别 `rule show`；其他查询动作逐条列入规则 | `rule add/del`、网络修改、未知选项 |
| `uci get openclash.config.en_mode` | `get` 及受限参数形式 | `set/add/delete/commit/import` |
| `nft list table inet fw4` | `list table` 等明确支持的查询形态 | `add/delete/flush`、脚本载入、未知选项 |

继续覆盖现有 `pwd/whoami/id/uptime/uname/ls/cat/wc` 中确认的安全形式。`mkdir/touch` 仅对参数和路径文本符合低风险规则的受限形式自动执行；系统目录、敏感路径、动态展开及无法归类的路径文本请求审批。`cp/mv` 有覆盖/删除源文件等风险，初版不因旧“读写”分类就自动执行。

路径筛选是基于 argv 的静态风险判断，不是远端文件系统沙箱：不解析远端符号链接、不验证运行时目录内容，也不承诺普通路径文本一定指向普通对象。因此低风险写入仍可能受远端符号链接或实际环境影响，执行能力由远端账户限制。设置帮助与发布说明须明确这个边界；本次不引入探测远端状态或强制隔离的额外执行协议。

这是一套可测试的命令规则，不声称能证明任意程序无副作用。未知命令在 ask/auto_edit 下进入审批，不再仅因未知分类就立即返回“未批准”。

## 命令家族和记忆

记忆身份绑定凭据 ID、凭据 generation、SSH 配置 ID、安全摘要和规则版本。客户端名称、标签和远端输出不能选择授权。

使用结构化 argv 匹配，不将审批范围作为用户提供的任意正则执行。多子命令工具采用显式动作路径，例如：

- `docker ps`：只覆盖该查询家族，不覆盖 `docker exec`。
- `uci get`：只覆盖 get，不扩大成全部 uci。
- `ip -4 rule show`：保留有意义的全局选项与完整动作，不扩大成 `ip -4`。
- `nft list table`：只覆盖该查询动作，不扩大成全部 nft。

已知命令家族还必须通过该家族的参数验证；未知选项、可执行载荷、危险包装器或无法唯一定位动作时，使用规范化完整 argv 的哈希，仅匹配同一命令。不能通过 `sudo`、`env`、绝对程序路径或相似前缀继承裸程序的宽泛记忆。

非查询命令可在请求审批模式记住，但只生成能明确展示并验证边界的家族；存在参数导致行为升级而规则未建模时回退为完整命令哈希。自动编辑模式仍对高危/未知请求逐次审批，无论曾在请求审批模式记住过什么。

记忆有版本和条数限制，每客户端所有 SSH 配置合计至多 128 条本地规则，全局默认集至多 128 条，仍受现有 64 KiB 私有凭据文件总上限约束。继承的全局规则只保存一份，不重复占用各客户端条数。达到上限不自动淘汰或放宽；提示清除记忆或改用允许一次。精确匹配保存哈希而不保存完整命令原文，避免把参数中的口令落入授权记录。此类记录只额外保存程序名与批准时间，重启后显示“程序名 · 精确命令 · 短指纹 · 批准时间”，支持按记录删除；不承诺从哈希恢复原始参数。

## 分客户端、分 SSH 的审批命令集

命令集位于“命名客户端 → SSH 配置 → 审批命令集”。客户端卡片按稳定身份隔离，即使两个客户端名称相同，也不能互相获得本地规则。同一客户端的两份 SSH 配置分别保存，不自动同步本地条目。

每份命令集显示：

- “继承全局默认命令集”开关，默认开启。
- 当前生效的命令规则及来源：“全局默认”或“当前 SSH”。
- 本地规则的新增、编辑和删除操作；完整命令精确匹配的条目可重新输入完整命令替换哈希，原始参数不回显、不持久化。
- “复制命令集”“粘贴命令集”“清空命令集”。保存前检查规则是否合法，并显示实际免审范围。

审批框中的“允许并记住”只写入当前客户端、当前 SSH 的本地集，不修改全局默认集。设置页修改命令集本身就是用户授权，MCP/AI 不得调用这些管理操作。

修改继承条目必须前往全局编辑器，那里明确展示影响所有继承者；不能在一个 SSH 中编辑继承条目却悄悄影响其他目标。若只想定制当前 SSH，可复制当前有效集，在当前 SSH 粘贴并替换，形成不再继承的独立命令集后编辑。

## 全局默认集与有效规则

设置页新增“全局默认审批命令集”，支持新增、编辑、删除、清空、复制、粘贴，初始为空，不擅自预置永久放行规则。

有效命令集 =（开启继承时的全局默认集）∪ 当前客户端当前 SSH 的本地集。按规范化规则身份去重，来源可以同时标注全局与本地；本版只管理允许规则，不增加隐含的拒绝规则或复杂优先级。

全局默认修改在保存成功后立即作用到全部继承者，包括已存在和之后新增的客户端/SSH；不需要逐一复制。关闭继承只影响当前客户端、当前 SSH。全局规则不能授予客户端认证、连接权限或白名单访问，也不能使失效的 SSH 安全摘要自动重新有效。

三种模式继续约束规则的效果：ask 可使用有效命令集免审；auto_edit 对高危/未知操作始终逐次审批，不因全局或本地预授权免审；full 不进行命令审批。命令执行禁用、目标失效及语法拒绝优先于所有命令集。

全局清空只清除全局默认规则，不清除任何 SSH 本地规则；继承者保存后立即失去这些全局授权。每个 SSH 的“清空命令集”同时清除其本地规则并关闭继承，使其有效审批命令集确实为空；不删除其他客户端/SSH 的规则，也不修改全局默认集。编辑器在执行前展示将清除的范围。命令集为空不改变当前模式：auto_edit 的内置低风险免审和 full 的免审仍然生效。

## 复制与粘贴

复制按钮导出当前有效规则的便携命令集，包含去重后的全局与本地条目。复制全局集时只导出全局规则。载荷使用带格式标识和版本的结构化文本；正常界面使用可读的命令列表和编辑表单，不要求用户手写内部 JSON。

导出不含 token、客户端身份、SSH 配置 ID/摘要、连接授权或审批模式。精确规则可携带哈希、程序名、规则版本，不导出原始参数。复制动作不会读取用户现有剪贴板。

用户点击“粘贴命令集”后自行粘贴内容，先解析、校验并预览，再保存。提供两种导入方式：

- 合并：增加到目标本地集，按规则身份去重，保留目标当前的继承开关与本地规则。
- 替换：以导入规则替换目标本地集，并关闭全局继承，使保存后的有效集与预览一致。

全局编辑器的合并/替换只作用于全局集，不修改本地集和各自的继承开关。目标处于 auto_edit 时，预览须标出其中高危/未知规则不会免审；不因导入而改变模式。

导入的规则重新绑定目标当前客户端 generation、SSH ID/安全摘要。导入不是继承源目标的授权；授权来自用户在目标编辑器显式保存。未知载荷版本、非法/超长规则、Shell 控制语法、重复冲突或不支持的家族均不部分应用，也不清空原集；给出可定位的错误，用户修正后再保存。便携规则版本不兼容时拒绝导入，不放宽解释。

合法规则按规范化身份去重；条数和总文件体积均在保存之前检查。只包含精确哈希的规则在复制后仍然只能匹配相同规范化命令，不能从哈希转换为宽泛家族。

## 审批交互与连接授权

新增命令审批视图，展示客户端、SSH 配置、原始命令、风险及原因、允许并记住的实际范围。按钮为“拒绝”“允许一次”“允许并记住”；不允许记住的请求仅显示前两个。默认焦点在拒绝。

沿用 60 秒审批窗口、取消/失焦/Escape 拒绝以及 bring-to-front。审批记忆由用户动作建立，AI 输入不能提出或修改放行规则。

连接权限与命令权限都缺少时，合并为一次内容明确的审批，展示本次会新建 SSH 会话以及连接授权会被记住；允许一次仅限命令本次使用。命令无需审批但连接尚未批准时，继续使用连接审批。

拒绝、超时、失焦、取消、凭据失效、SSH 配置变化均不建立命令或连接记忆。只有本次请求仍有效且所需授权成功保存后，才可能发送命令。

## 存储、撤销与竞态

命令记忆、每个客户端/SSH 的继承开关及全局默认集共同扩展现有私有凭据存储，不新增独立后台服务。全局集存放在文件顶层，各客户端记录分别保存绑定 SSH 安全摘要的本地集与继承设置；因此可以复用同一套串行写入、版本检查与失败关闭机制，不跨两份文件拼接授权事务。凭据文件升级至 v3，兼容读取 v1/v2：默认集和本地集为空、已授权目标默认继承；首次成功保存时升级，不旋转现有 token。旧插件不能读 v3，发布文档须说明降级边界。

重置/撤销客户端同时清除其命令记忆；删除白名单、SSH 安全摘要变化、规则版本变化使相关记忆失效。重命名客户端不影响其身份。

设置页能编辑每个客户端、每个 SSH 配置的本地命令集和全局默认集，并管理继承与便携复制/导入。每个编辑器保存时提交打开编辑器时的基准版本；期间若审批框或另一个设置操作已更改相关集合，保存拒绝覆盖并提示重新加载，不丢失较新的批准/撤销。

模式切换、编辑/删除/清空/替换规则、切换继承、全局修改或撤销客户端时，立即使受影响请求捕获的授权版本失效。全局修改影响全部继承者，本地修改只影响对应身份/SSH；实现可采用保守的服务级请求失效，但不得使其他目标获得或丢失持久规则。打开标签页之前和发送命令之前重新校验身份、配置摘要、模式、规则和当前版本。旧审批不能覆盖新的撤销，旧编辑器不能复活被删除的规则。

减少权限的更新在保存过程中即按撤销处理；磁盘保存失败时，受影响授权在当前运行中保持禁用，提示重试，不用旧全局集或旧本地集继续放行。增加权限只在成功保存后生效。保存“允许并记住”失败不伪装成已记住，也不自动降级为允许一次执行。

审计记录模式、风险、结果和规则标识，不记录命令原文、输出或完整匹配载荷。实际执行失败仍不自动重试；既有审计不可用及未知执行结果语义继续生效。

## 旧配置与 MCP 合同

旧配置按保守方式读取，避免从原来较窄的权限自动扩展为自动编辑：

| 旧值 | 新行为 |
| --- | --- |
| `none` | 命令执行禁用 |
| `readonly` | 请求审批，空命令记忆 |
| `readwrite` | 请求审批，空命令记忆；用户可以选择自动编辑 |
| `full` | 完全访问 |
| 缺失/非法/摘要过期 | 不授予自动执行权限，显示需重新确认 |

保持四个工具名称、输入形态与连接配置；同步更新共享 schema、dispatcher、运行时、工具描述和结构化输出，使用 `approval_mode`、启用状态和命令风险等真实字段，不将新模式伪装成旧 `operation_tier`。返回结构有意更新；硬编码旧输出字段的调用方需适配，文档明确记录。不让 MCP 调用修改模式或授权记忆。

常规拒绝返回清楚的原因，区分用户拒绝、审批超时、命令禁用、语法不支持及授权失效；不再把所有情况统一解释为未在 Tabby 批准。

## 影响范围

- plugin：命令解析/分类、模式策略、配置迁移、gatekeeper、审批 presenter/modal、运行时注入和发送前复核。
- companion：私有凭据合同、解码/持久化、客户端授权修订、MCP 输出与错误说明。
- ipc-contract：模式、风险、授权查询和执行结果 schema 及边界测试。
- 设置页：三种模式、禁用能力、分客户端/SSH 的可编辑命令集、全局默认集、继承开关、复制/粘贴预览，中英文说明及组件测试。
- 文档与验收：README、接入说明和模式/迁移说明。

实现优先复用现有结构，不引入新依赖，不把单命令工具扩展成通用 Shell 脚本执行器。本设计不授权安装到个人 Tabby、修改 AI 配置、提交、推送或发布。

## 验收

1. 请求审批：四条原始查询首次均弹窗；允许一次再次仍弹；允许并记住后同家族免审，其他子命令不能复用。
2. 自动编辑：四条查询及受限低风险编辑免命令审批；删除、系统修改、解释器、未知命令每次弹窗，旧记忆不能旁路。
3. 完全访问：合法单命令免命令审批；客户端、连接、白名单、语法和审计检查仍执行。
4. 参数与匹配反例覆盖全局选项位置、危险参数、相似程序名、绝对路径、包装器、引号、超长/控制字符及 Shell 组合符。
5. 记忆跨重启有效且按客户端、generation、配置摘要隔离；重置、撤销、清除、模式切换立即失效。
6. 取消、超时、失焦、持久化失败和旧弹窗/写入竞态均不能增加权限或发送未批准命令。
7. v1/v2 凭据读取和 v3 写入、旧命令等级迁移、MCP schema、设置和中英文界面回归通过。
8. 运行 typecheck、单元/脚本测试、HTTP 集成、build、pack check、diff check。真实 Tabby 交互与真实 SSH 验收单列证据，不能用模拟测试替代。
9. 同一客户端的不同 SSH、不同客户端的同一 SSH，本地命令集均独立；编辑一份不改变另一份。
10. 全局集初始为空；修改/删除后既有继承者立即生效，关闭继承者不受影响；新目标默认继承且仍须通过连接授权和白名单。
